# 维修可达候选审计契约

## 目的

项目经理不仅需要看到最终路线，还要能追问：为什么选它、其他位置为什么不行、失败发生在入口、梯具、路线还是设备检修区。候选审计工具把这些机器证据保存在 Revit 进程内的 MCP 快照中；PPT 只负责把证据翻译成人话。

维修可达保持为 MCP 协作能力，不在稳定功能区按钮中固化项目判断。任何支持 MCP 的 AI 都可以调用同一组工具。

> 天花 400×400 伸手检修已升级为独立契约，见 [maintenance-hand-reach.md](maintenance-hand-reach.md)。本文档描述墙门完整维修与旧 800 天花口候选审计。

## 工具

- `analyze_maintenance_route_candidates`：执行候选审计，不写入或显示模型结果。
- `get_maintenance_route_candidates`：按目标、范围、状态和入口类型分页读取同一快照。
- 原 `analyze_maintenance_reachability` 与审批、显示工具继续用于最终选中方案。

## 搜索范围

契约名称为 `reportable_candidate_schemes`，不等于穷举所有数学路径：

- 侧墙入口按现有约 400 mm 边界采样保留；不足以容纳入口的短墙段不生成位置方案。
- 天花入口的正式选择仍按原 80 mm 顺序搜索，候选汇报按 400×400 mm 空间桶保留代表点；选中点永不因分页或代表上限丢失。
- 天花 raw universe、进入目标连通域的 eligible 样本、去重后代表数、保留数、遗漏数和截断状态分别计数。
- 每个保留的“入口×设备×通行档位”只保存一条确定性 A* 路线；无入口、无目标点、无连通路线或碰撞均保存明确失败阶段。
- 碰撞服务当前遇到第一个冲突或不可验证图元即返回，因此 blocker 是主阻挡证据，不宣称列出全部阻挡物。
- 管道豁免是**设备目标级**的“近端局部支管”判断，不再按系统名全组删除。只有普通管道、管件或管道附件可进入判断；软管、风管、喷淋管、其他管道、结构与楼板仍为障碍。
- 系统证据只接受 Revit 内置管道系统类型，或连接器所属 `MEPSystem` 的系统类型；本地化名称参数、构件名称和类型名称不作为豁免证据。可靠值必须明确包含“冷媒”或“冷凝水”，其中“冷媒水”明确排除。
- 管线必须与目标设备位于同一宿主模型或同一链接实例，管径不大于 100 mm；普通管段长度不大于 1800 mm，管件/附件最长外形不大于 650 mm；至少一个曲线端点或连接器距设备包围盒不大于 300 mm，全部端点和构件包围盒都不得离开设备外扩 1200 mm 的局部邻域。
- 若另一设备也接近该管线，且当前设备没有至少 250 mm 的唯一归属优势，则保持为障碍。任何缺失、空值、异常、无端点、尺寸未知或空间归属模糊也都按障碍处理。
- 豁免只作用于该目标设备自己的安全网格、天花入口/梯具、路线和检修区碰撞；侧墙入口仍按可供多设备共用的全组障碍口径保守检查，不改变其他设备的结果。被豁免构件仍保留在 `EvidenceSources`，并在 `exemptPipeEvidence` 返回构件身份、系统证据来源、原因、近端距离、长度和管径。

JSON 固定返回：

```json
{
  "scopeDefinition": "reportable_candidate_schemes",
  "allPathsEnumerated": false,
  "routePolicy": "one_deterministic_astar_path_per_retained_entry_target_profile",
  "rawSampleCount": 0,
  "eligibleSampleCount": 0,
  "deduplicatedCount": 0,
  "retainedCount": 0,
  "omittedCount": 0,
  "truncated": false
}
```

## 选择和展示排序

最终选择沿用生产规则：优先 700 mm 完整通行；侧墙入口优先于天花入口；墙入口按未覆盖设备数、既有入口复用、人字梯和稳定候选键做贪心选择；600 mm 是需复核的降级档位。

`reportRank` 只服务审计阅读：选中项、可行备选、不可验证、冲突依次展示，再按档位、入口、梯具、路线长度和稳定键排序。路线长度没有参与当前最终选择，MCP 会显式返回两套策略，避免把汇报排序误说成决策算法。

## 状态与证据

每条候选包含：几何状态、选择状态、失败阶段、稳定原因码、人话原因、主阻挡构件、是否有路线、路线长度和转折数。路线点默认不返回，只有 `includeRoutePoints=true` 时分页输出。

审批返回的一次性 `approvalToken` 只解锁一次显示。`show_maintenance_reachability` 先验证快照与令牌，只有显示事务成功后才消费并清空令牌；显示失败不消费。同一令牌不能重复写模型，复核状态会标记 `visualized_from_single_use_approval` 和 `approvalTokenConsumed=true`。

坐标、ElementId、UniqueId 和内部候选键供 AI 追溯，不直接放入项目经理 PPT。PPT 应回答“结论—为什么选—最强备选—其他方案在哪一步失败—哪些仍需专业确认”。

候选快照目前保存在 Revit 进程内存；可在同一进程中切换 AI 读取，Revit 重启后需重新分析。永久候选台账属于后续能力，不在本原型中冒充已完成。
